# Doctours reply system: skills, typed routing, and a real human handoff

This replaces the single ~41k-token system prompt with a **bounded workflow**:
- **Models interpret and word the reply.** A typed router classifies the message; an LLM writes the connective text.
- **Code holds authority.** It decides escalation, renders every commercial fact, controls links and writes, and validates the output shape.

Every message runs through the same steps. Each step is traced and can be tested on its own.

```bash
npm install
cp .env.example .env        # add your keys (see "Setup")
npm run reply -- --input messages.json --output replies.json
```

`messages.json` is a JSON array of `{ "id", "text" }`. `replies.json` is a JSON array of `Reply` objects, one per input, in the same order. Diagnostics go to stderr, so stdout stays pure JSON when `--output` is omitted.

## How it works

```
input guards ─► typed router (Jev, per chunk for long input) ─► policy gate ─┬─► handoff (code, one sentence, STOP)
                                                                             ├─► clarify (code, one question)
                                                                             └─► skills ─► code-first evidence ─► writer (LLM, JSON + clause tokens)
                                                                                    ─► validators ─► ≤1 repair ─► validated fallback ─► commit writes ─► Reply + trace
```

### 1. Input guards (code, full message)
- **Normalise.** The text is normalised (NFKC) and **never truncated**. Messages up to 12k characters are routed whole. Longer ones are routed chunk by chunk, and every chunk is classified before anything is drafted. Above a 50k hard limit, the patient gets a deliberate, documented handoff instead of silent truncation.
- **Card data.** Fragments ("card ending in 4242", "last four …", CVV) and full card numbers with any separators (spaces, hyphens, dots, non-breaking spaces, full-width digits) are found. So are 13–19 digit runs next to card words even when the Luhn check fails. The exact matched text is replaced before any model or trace sees it, and output is checked with separators removed.
- **Human fast path.** Conservative patterns catch clear requests ("talk to a human", "get me a manager"). They're evaluated sentence by sentence, so a negation or identity question ("are you a bot?") in one sentence cannot hide a request in another. These requests hand off in about 2 ms, with no model call.
- **Injection.** Prompt-injection phrasing is flagged.

### 2. Typed interpretation: one call, many questions
The router answers ~30 typed questions in one call:
- **Booleans:** needs_human, medical_urgent, self_harm, abuse_or_legal, prompt_injection, pausing, high_engagement, one per skill.
- **Choices:** unsupported_action, payment_mode, the clinic and package referred to or explicitly preferred (options built from tool data), style, target window.

Adapters share one `DecisionAdapter` interface:
- **Jev** (TypeSafe `/v1/systemone`), the default when a key is set;
- **Laya**, self-hosted on the same API (`LAYA_URL`);
- **an LLM classifier** answering the same questions in JSON.

**Merge rules (explicit, and recorded in every trace):**
- **Second opinion.** The second adapter is consulted when a terminal signal is uncertain (0.35–0.6), and to confirm any unsupported-action signal.
- **Terminal signals take the max.** Whenever the second adapter runs, for any reason, human, medical, self-harm and abuse each take the **max** of the two scores. The trace records this as a max score, not a calibrated probability. Primary 0.35 plus secondary 0.80 escalates.
- **Unsupported actions have three explicit outcomes:**
  - **`agree`**: both flag an action, so it escalates.
  - **`disagree`**: the second adapter says none, so there's no escalation from the action alone. Nothing can be executed anyway (tools are read-only to the model), and validators block promises.
  - **`confirmation_unavailable`**: the second adapter failed or isn't configured, so it escalates conservatively.

### 3. Policy gate (code)
Fixed priority: safety → human request → unsupported action (with its consensus) → abuse or legal threat → clarify (ambiguous clinic) → answer.
- A **policy question** ("what's your refund policy?") is answered. A **request to execute** it ("move my $300") escalates.
- A **payment-link request** is never escalated.

**Handoff is terminal.** Code writes one short sentence per category and sets `escalate: true` and `escalationReason`. There's no writer call, no business tool and no write after a handoff.

### 4. Skills: what's loaded per turn
The old prompt is decomposed into `domains/hair/core.md` (always loaded, ~2.7k tokens) and 17 skill files. `domains/hair/SOURCE_MAP.md` maps each of the old prompt's ~52 sections to a rule id, or to "dropped" with a reason.
- **Selection.** Skills with router score ≥ 0.6 load, plus their `depends_on`, minus anything a loaded skill `suppresses`.
- **Ordering.** Skills are ordered hard → stage → guideline, then by id, so the same input always produces the same order.
- **Conditional branches.** Sections like `### [when financing=yes]` are chosen from patient data in code, so the model never sees branches that don't apply.

### 5. Evidence: typed entities and clause tokens
Code prefetches the tools the router's intents need. Results become **typed entities**: clinics `C1…`, packages `P1…` and the assessment `AS`, plus links `L1…` and photos `IMG1…`.

**The writer never states a commercial fact in its own words.** It references clause tokens such as `{{P2:price+deposit}}`, and code renders the entity name and value together ("Gold is $4,500 USD with a $600 deposit"). A price therefore cannot be attached to the wrong package. The available clauses are:
- **package:** price, deposit, price+deposit, inclusions, weekdays, note;
- **clinic:** location, specialty, packages, package-count, doctors, best-for;
- **assessment:** graft range.

**Tools.** The registry holds exactly the packet's 14 functions:
- arguments are validated;
- the `…Tool` aliases are accepted and phantom tools are rejected;
- the model can't call write tools.

A bounded tool loop (≤ 2 rounds, ≤ 4 calls) runs only when a needed fact is still missing after prefetch.

### 6–8. Writer, validation, repair, fallback
The writer returns JSON: text with clause tokens, link and attachment ids, claims with sources, intent, follow-up and a memory patch. **Validators** then check:
- **Unknown or unavailable tokens**, typed URLs, unrequested clinic-page links, echoed card digits.
- **Quantity guard.** Any money amount or unit quantity the writer typed itself (such as "$500", "100 USD", "20 hotel nights", "3 packages", "10%") must be a figure stated verbatim in a loaded rule, like "$25" or "24 hours". A number the patient quoted ("you quoted me $100") is never authority.
- **Claim sources must exist.** An unknown source is a soft violation, since tokens already guarantee the rendered facts.
- **Content rules:** off-channel promises, head-covering advice, assessment turnaround times, financing math, markdown, length.

**Repair and fallback:**
- Hard violations get **one targeted repair**.
- If that fails, the **rejected draft is discarded entirely**: text, memory, follow-up and claims.
- A **fallback** is built as a complete result from clause tokens chosen by what was asked (price, inclusions, weekdays, doctors, specialty, which packages, payment path, consultation). It passes through the **same render and validation** as a draft before anything is committed.
- With no matching template, the reply is "I don't have that exact detail." That's a missing *detail*.
- If any adapter flagged an *action*, the fallback hands off instead.

### 9–10. Writes and finalise
- **Writes happen once, after the final result is validated, never after a handoff.** Selection writes come only from the router's *explicit preference* decisions, not from a package merely mentioned in a question, and clinic/package membership is enforced.
- **Memory.** It comes only from an accepted draft, never from a rejected one.
- **Follow-up.** A pause with no named window defaults to a 1-month follow-up.
- **Final checks.** The whole Reply is validated with zod.

### Provider outages
If the writer's provider fails after retries, the turn is re-run on a fallback writer. Usage from calls that completed before the failure is kept, and the failed call's cost is marked unknown. Evals use `--failover 0` so each model is measured on its own.

## Observability

**Zero-setup dashboard.** `npm run dashboard` writes one offline HTML file from `traces/*.jsonl`, `examples/` and `eval/results`, then opens it. It has three tabs:
- **Overview:** run comparison.
- **Traces:** each message's timeline (guards, router, gate, skills, tools, LLM calls, output battery, writes), router signals and merge decisions, rules fired, skills and why each loaded, tool calls with results (emails and phone numbers masked), writer attempts with violations, claims, and the exact prompt.
- **Eval runs:** a pass/fail grid per case and run, linked to traces.

**Optional OpenTelemetry.** Set `PHOENIX_COLLECTOR_ENDPOINT` (or `OTEL_EXPORTER_OTLP_ENDPOINT`) and each reply is exported as an OpenInference span tree: CHAIN, GUARDRAIL, TOOL, LLM, EVALUATOR. For a local Arize Phoenix UI:

```bash
docker compose up -d phoenix        # UI + collector on http://localhost:6006
```

Export is off by default and failure-silent. It never changes replies.

## Review fixes
An external review reproduced seven defects. Each is fixed and pinned by a regression test:

| Finding | Fix |
|---|---|
| Validator accepted wrong facts (swapped tokens, "20 hotel nights", "100 USD") | Clause tokens render name and value together; quantity guard; claim sources checked |
| Rejected draft still wrote memory and a follow-up | Complete fallback result, validated before commit; the draft's metadata is discarded |
| Formatted card numbers partly redacted | Span-based redaction including separators; separator-insensitive output check |
| Router averaging suppressed a human signal (0.35 + 0.80 → 0.575) | Max merge for all terminal signals; explicit action consensus states |
| Input truncated at 2,000 characters | Full-message guards, chunked routing, explicit hard limit |
| Cost excluded routing and checks | Per-stage usage ledger with estimated and unknown costs |
| `.env` read after defaults were captured | `getDefaultOptions()` called after `loadEnv()` |

It also split the scorer's write checks (`noBusinessWrites` / `noWritesAtAll`), made the fallback specific to the question, and added CI.

## Evaluation sets
- **`eval/packet.cases.ts`:** the packet's 5 messages, checked against its grading facts.
- **`eval/dev.cases.ts`:** 39 development and regression cases. Thresholds and router wording were tuned against them, so they are **not** a generalization claim.
- **`eval/holdout.cases.ts`:** a **frozen holdout**, authored by a separate agent from the packet's rules only, without access to the code, prompts, dev cases or expected outputs. Its SHA-256 is recorded in `eval/HOLDOUT.sha256` before the first run. It's excluded from `--set all`, and nothing is ever tuned on it. If a holdout failure informs a fix, that set becomes regression data and a fresh holdout is authored for the next claim.

**Answer-key hygiene:** `tests/leakage.test.ts` fails the build if any expected sentence, sample message or the ungrounded consultation duration appears in `src/` or `domains/`.

## Decisions on conflicts in the packet
- **Escalation reply vs the old VOICE rules:** the handoff is rendered by code, outside the writer.
- **"Don't resend links" vs "can I pay from the assessment?":** the payment skill includes the assessment link when the patient asks how or where to pay.
- **Consultation duration:** "15 to 20 minutes" appears only in the expected output, so it's omitted (and a test enforces that).
- **Refund/transfer:** a policy question is answered; a request to execute it escalates.
- **Stale "Message Classification: pricing/high":** ignored; the router re-classifies every message.
- **Fixture mismatches** (no `tentativeProcedureDates` argument, `updateUser` accepts names only, clinic `url` is a Doctours page, no `ai_context.status`, `getPatientContext` doesn't persist writes): the code works with the tools as they actually are.

## Setup

**Prerequisites:** Node ≥ 22. CI runs typecheck and tests offline on every push.

**Keys** go in `.env` (gitignored; the code reads them only from the environment):

| Variable | Needed for |
|---|---|
| `DEEPSEEK_API_KEY` | default writer (`deepseek-flash`) and the LLM classifier |
| `GEMINI_API_KEY` | `--writer gemini` (`gemini-3.8-flash`) |
| `OPENROUTER_API_KEY` | `--writer qwen` (`qwen/qwen3.8-27b:free`; the free tier allows 50 requests/day) |
| `TYPESAFE_API_KEY` | optional Jev router; without it, the LLM classifier routes alone |
| `LAYA_URL` | optional self-hosted Laya router |
| `WRITER_MODEL`, `ROUTER`, `CLASSIFIER_MODEL`, `OUTPUT_BATTERY` | optional defaults (read after `.env` loads) |

**Commands**

```bash
npm run reply -- --input eval/packet.messages.json --output replies.json --trace traces/run.jsonl
npm test                                                    # unit tests, offline
npm run typecheck
npx tsx eval/run.ts --writer deepseek --set dev --k 3 --max-usd 1 --publish      # live eval with a spend cap
npx tsx eval/run.ts --writer deepseek --set holdout --k 3 --max-usd 1 --publish  # frozen holdout
npm run bench:table -- --write                              # regenerate the README results table
npx tsx eval/baseline.ts --writer deepseek --set holdout    # original monolithic prompt, same scorer
npx tsx eval/toolcalling.ts --models deepseek,gemini,qwen   # tool selection / argument validity
npm run dashboard                                           # local observability dashboard
```

## Limitations
- **Small, synthetic cases.** The dev and holdout sets are synthetic and small, so passing them is evidence, not proof. Thresholds were set on the dev set.
- **Jev costs are estimates** from the published rate, until billing confirms them.
- **Laya was not measured** (it needs a Python server). It's a drop-in via `LAYA_URL`.
- **Qwen runs** use a free, rate-limited, fp4-quantized OpenRouter endpoint.
- **Gemini pricing** rises to $1.50 / $7.50 per 1M tokens on 2027-01-01.
- **Fixture tools are stateless.** Writes are validated and recorded but not persisted between messages (each message is a fresh turn on the same history, as the packet specifies).
